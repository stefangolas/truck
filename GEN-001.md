## 2. What ARR-002 actually built (the surface GEN-001 generalizes)

ARR-002 is a **pairwise, line/circle, rank-0** intersection layer. Its
arrangement-facing surface is small and concentrated in three files:

- `curve2d.rs` — `DevelopedCurve2D{Line, CircularArc}`, `CurveOccurrenceProvenance`,
  `LineSegment2`, `DirectedCircularArc2`.
- `xmonotone.rs` — `XMonotonePiece2{Line, CircularArc}`, `MonotoneKind`,
  `make_x_monotone`, the circular `atan2` critical lattice.
- `intersection.rs` — `intersect_x_monotone` (2×2 family dispatcher),
  `PairIntersectionResult`, `CertifiedIntersection2`, `ContactKind`,
  `IntersectionIdentity`, the exact discriminant solvers, the chord-side test.

It sits on two **family-agnostic, reusable kernels** (do not re-derive):

- `exact.rs` — `Expansion` (Shewchuk), `CertifiedInterval` (directed rounding),
  `exact_sq_dist`/`exact_dot2`/`cross_exp`. The one exact-arithmetic copy in the
  workspace; `look` consumes it via the patch.
- `source_evidence.rs` — the five-factor orientation-evidence model with
  `computable_normalized_sign_count` as a tripwire (0 on the compressed path).

And on two **already formal-system-faithful** layers:

- `ambient.rs` — rank authority. Already rank-parametric (`DeckVector0/1/2`,
  `CertifiedRank0/1/2`, `CertifiedAmbientLattice`), already uses the five
  distinguishable states (authoritatively absent / certified / declared-but-
  uncertified / undetermined / contradictory), already cites D7/D8/D9/§VII/D16/§IX.
  `certified_rank()==0` supports no ambient conclusion.
- `deck.rs` — deck arithmetic. `solve_axis_aligned` (the four-way `Unique`/
  `NoCompatible`/`Multiple`/`Indeterminate` solver) and `deck_cover_interval`
  (which **is** D16 / Lemma 1, `K_ij = {k : (Bᵢ−Bⱼ) ∩ {kg} ≠ ∅}`, with
  false-positive-acceptable / false-negative-P0 soundness and a period-
  resolvability guard). **Rank-1, single-axis, axis-aligned only.**

The shape of GEN-001 follows directly from the gap between the pairwise
arrangement surface and the formal system, *not* from rebuilding the kernels.

## 3. Audited assumptions

Format: `file/type/function — current assumption — why it blocks — minimal
compatible generalization — required now (impl) or representability only`.

### A1. Curve family is exactly {Line, CircularArc}

- `curve2d.rs:226` `enum DevelopedCurve2D{Line, CircularArc}`;
  `xmonotone.rs:305` `enum XMonotonePiece2{Line, CircularArc}`;
  `intersection.rs:399` `intersect_x_monotone` 2×2 dispatcher;
  `xmonotone.rs:482` `make_x_monotone` match.
- **Assumption:** only analytic lines and circles exist.
- **Blocks:** rational Bézier / NURBS / affine-conic pcurves cannot enter the
  arrangement without a new variant in every enum and a new matrix arm — exactly
  the "invasive rewrite" the breakpoint exists to prevent. Also forces any
  future family to re-implement monotone decomposition and intersection from
  scratch against family-specific math.
- **Generalization:** a `CurveSpan2` contract — stable span id, source
  occurrence, authoritative parameter domain, traversal direction, certified
  evaluation enclosure, derivative/branch info, optional analytic fast-path
  classification, deterministic debug representation. ARR-003 dispatches on the
  contract, never on family variants. A sealed trait plus stable tagged wrapper
  is acceptable; unconstrained `dyn` is not (it defeats deterministic identity).
  Analytic line/circle remain optimized implementations of the contract.
- **Now:** contract + representability; **one working non-analytic
  implementation** (a polynomial Bézier) to validate the abstraction has a
  second member. Do not force analytic circles through Bézier conversion.

### A2. Exactly two curve incidences per event

- `intersection.rs:271` `CertifiedIntersection2{lhs_parameter, rhs_parameter,
  lhs_location, rhs_location, …}` — exactly two parameter slots;
  `intersection.rs:164` `IntersectionIdentity::CurveIntersection{lhs_edge_use,
  rhs_edge_use, intersection_index}` — pairwise; `intersect_x_monotone(lhs,rhs)`
  — pairwise signature.
- **Assumption:** an event involves exactly two curves.
- **Blocks:** a genuine triple or higher-multiplicity event must be represented
  as N pairwise pseudo-events, violating hard-constraint #7 ("no splitting a
  genuine high-multiplicity event into pairwise pseudo-events") and making one
  stable event identity across ≥3 branches impossible. The module doc itself
  defers "triple intersections (handled by the sweep, ARR-003)" — but the *type*
  cannot hold a 3-way event, so the deferral is currently structural, not just
  scheduling.
- **Generalization:** an `IsolatedEvent2` carrying an arbitrary number of
  incident branch records (each = span id + parameter enclosure + germ), under
  one stable `EventIdentity`. The pairwise solver becomes a *contributor* that
  emits branch records into a shared event keyed by certified root identity, not
  the event itself.
- **Now:** representability. The pairwise solver stays the producer; ARR-003
  merges by identity. GEN-001 must demonstrate ≥3 branches under one identity
  (Phase 4 validation).

### A3. Only isolated point intersections; overlap is a bare tag

- `intersection.rs:344` `PairIntersectionResult::Intersections(Vec<CertifiedIntersection2>)`
  (points only); `intersection.rs:297` `PairUnsupported{Overlap, UnrelatedTangency,
  CoincidentCircles}` — tags carrying no interval, participants, or correspondence.
- **Assumption:** contact is 0-dimensional; positive-dimensional contact is
  unsupported and undetailed.
- **Blocks:** FORMAL_SYSTEM §IX admits overlaps *normalized by a separately-
  proven overlap subsystem*; `PairUnsupported::Overlap` cannot represent the
  result of that subsystem. Defeats GEN-001 Phase 6.
- **Generalization:** `ContactComponent2 = IsolatedEvent(IsolatedEvent2) |
  CommonArc(CommonArc2)`, where `CommonArc2` carries one support fragment,
  every participating occurrence, parameter correspondence on each, relative
  orientation, multiplicity, the certified basis for common support, and
  endpoint event identities. The type must not make later common-factor
  extraction impossible (it can stay deferred).
- **Now:** representability + the minimal certified overlap cases (identical
  source/support provenance; identical analytic support with certified
  overlapping parameter intervals; identical homogeneous Bézier under identity
  or certified affine parameter reversal). Full gcd/implicitization deferred.

### A4. Regular first derivatives only

- `xmonotone.rs:80` `MonotoneKind{StrictlyIncreasingX, StrictlyDecreasingX,
  Vertical}` — assumes a certified nonzero dx/dt (or exactly-vertical);
  `xmonotone.rs:426` `MonotoneDecompositionFailure` has no stationary/singular
  variant; `intersection.rs:144` `ContactKind{Transverse, Tangent}` — only
  regular even/odd contact.
- **Assumption:** every piece is regular (nonzero first derivative); every
  tangency is a clean contact.
- **Blocks:** cusp / stationary / singular parameterizations (FORMAL_SYSTEM
  §XI D24 singular-link, cone-apex `Collapse`, cusp candidates) cannot be
  represented — they are forced to `Unresolved` or misclassified. An odd-order
  inflection-tangency (nonzero higher jet, zero first derivative) has no
  `ContactKind`. A zero first derivative is treated as invalid rather than as a
  signal to search the jet.
- **Generalization:** a `BranchGerm` model —
  `Regular{first_nonzero_order:1} | StationaryRegular{first_nonzero_order:k} |
  CuspCandidate | Singular | Unresolved` — plus a derivative-jet operation
  `k = min{j≥1 : C^(j)(t₀)≠0}` on `CurveSpan2`. `MonotoneKind` becomes a
  *certified regular-piece label*, not the only piece kind. No singular branch
  may be silently treated as an ordinary tangent.
- **Now:** representability (the germ variants + the derivative-jet contract on
  `CurveSpan2`). A real stationary test subject requires the non-analytic curve
  from A1's MVP — e.g. a rational quadratic with a cusp, or a weight vanishing
  on the span.

### A5. Endpoint identity is Regular-vertex only

- `source_evidence.rs:91` `SourceVertexKey{ShellVertex, Absent}`;
  `curve2d.rs:57` provenance carries only `start/end_vertex_id: SourceVertexKey`;
  `xmonotone.rs:156` `ArcPieceEndpoint{SourceVertex, Critical}`;
  `intersection.rs:153` `IntersectionIdentity{SourceVertex,
  ArtificialMonotoneSplit, CurveIntersection}`.
- **Assumption:** endpoints are regular source vertices or artificial monotone
  splits; there is no collapsed-stratum (pole/apex) or native-boundary endpoint.
- **Blocks:** FORMAL_SYSTEM §D9
  `Endpoint = Regular(u) | Native(n,t) | Singular(σ)` is only partially
  represented (Regular ≈ `ShellVertex`; no Native, no Singular). Cone-apex and
  sphere-pole faces cannot carry their endpoint semantics.
- **Generalization:** an `EndpointDescriptor` enum with Regular/Native/Singular
  flavors; `EventIdentity` gains `CollapsedStratum(σ)` and `DeckTranslated{…}`
  variants.
- **Now:** representability only. Native/Singular endpoints are unreachable
  until the evidence seam certifies collapsed strata — and today it certifies
  none (`source-evidence-seam`: declared rank 2 on 1,357 faces, **certified
  rank 2 on zero**). The type must admit them; the population is downstream.

### A6. Rank-0 coordinates at the curve layer; deck arithmetic is rank-1-axis-aligned

- `curve2d.rs`/`xmonotone.rs`/`intersection.rs`: developed coordinates are plain
  `Point2<f64>`; no piece, event, or record carries a deck label `δ`.
  `deck.rs:361` `DeckGenerator` = one `periodic_axis` + one `signed_period`;
  `deck.rs:701` `CertifiedDeckInterval::Finite{min,max:i64}` = a 1-D range.
  (`ambient.rs` is already rank-parametric.)
- **Assumption:** the developed plane is Rank-0 at the arrangement-curve layer;
  where rank exists it is a single axis-aligned period.
- **Blocks:** rank-2 (torus) deck enumeration; non-axis-aligned period matrices;
  carrying deck displacement on every event, branch, and edge (§VII potentials,
  §VIII D16/Lemma 1, §IX `~_Λ` identification).
- **Generalization:** rank-parametric `DeckLabel` (≤2 integer components), a
  `DeckLattice` from a period matrix `P`, and a rank-aware
  `enumerate_translated_copies(Bᵢ, Bⱼ, P)` that generalizes `deck_cover_interval`
  from one axis-aligned period to a rank-≤2 period matrix (Lemma 1 holds for any
  rank; the outward-rounding and period-resolvability machinery in `deck.rs`
  lifts directly). Every arrangement-facing record carries an optional
  `deck: DeckLabel`.
- **Now:** representability (DeckLabel on records) + the rank-1 → rank-2
  enumeration generalization, reusing `deck.rs`'s proven core. Rank-2 needs only
  to be *enumerable* and tested synthetically; no torus adapter is wired (the
  seam certifies 0 rank-2 today). Never scan a fixed `-2..=2` range — D16
  computes the finite candidate set from the enclosures.

### A7. Chord-side membership uses rounded representative endpoints (the named GEN-001 audit item)

- `intersection.rs:900` `expected_orient_sign`; `arc_location_for_line_root`
  (~`:1467`) and `arc_location_for_circle_root` (~`:1530`) read
  `s = arc.start.point(); e = arc.end.point()`. For a `SourceVertex` arc
  endpoint, `.point()` (xmonotone.rs:169) is the *evaluated* `arc.point_at(t₀)`
  in `f64` — a rounded representative.
- **Assumption:** the rounded evaluated endpoint coordinate is a usable chord
  endpoint, under the ≤π monotone-piece precondition.
- **Why it is *currently* sound:** the ≤π precondition (a nondegenerate
  x-monotone circle piece has distinct endpoints and sweep ≤π) makes the
  chord-side sign an exact membership test, and `LocationOnPiece` is exhaustive —
  a straddle goes to `Boundary` → endpoint-admission or `Undecidable`, never an
  invented membership. No tolerance creates topology.
- **Blocks:** GEN-001's own completeness criterion — "ARR-003 must not interpret
  those representative endpoint coordinates as semantic identities." If ARR-003
  relaxes the ≤π precondition, or threads `arc.start.point()` into event
  ordering, topology is at risk.
- **Generalization:** replace the chord-side representative test with a
  **certified branch/germ** test (the germ model from A4): membership is decided
  by certified local branch behavior, with the endpoint's *authoritative
  parameter* (source trim value or critical enclosure) as the semantic input —
  never the rounded `arc.start.point()`.
- **Now:** implementation. This is the concrete, well-scoped win GEN-001 exists
  to land before ARR-003. It depends on A4's germ contract.

### A8. x-critical detection is the circular `atan2` lattice

- `xmonotone.rs:689` criticals are `t_k = atan2(b,a) + k·π` with a
  `parameter_enclosure` widening and the structural-algebraic fallback
  `source_endpoint_is_structurally_at_critical` (`:893`);
  `intersection.rs:1274` `interval_atan2` for arc-parameter recovery.
- **Assumption:** x-monotonicity splits come from the analytic circle's
  critical lattice.
- **Blocks:** a generic parametric curve's x-criticals are the roots of
  `dx/dt = 0`, not an `atan2` lattice — they require root isolation.
- **Note (not a current soundness bug):** the existing `atan2` use decides only
  *parameter enclosure / ordering keys*; topology is decided by the exact
  `orient` test. So hard-constraint #4 (no principal-branch `atan2` topology) is
  already respected. The generalization is about *coverage* (generic curves),
  not correcting a defect.
- **Generalization:** a generic x-critical isolation via certified root-finding
  on `dx/dt` (GEN-001 Phase 3), with the circle's `atan2` lattice retained as
  the analytic fast path.
- **Now:** implementation only for the generic (Bézier) path; the analytic
  circle path stays intact.

## 4. Invariants ARR-002 already enforces (carry forward unchanged)

These are the load-bearing correctness properties. GEN-001 must not regress any.

1. A representative point is an evaluation hint, not event identity
   (`CertifiedIntersection2.point` doc, intersection.rs:266).
2. Interval overlap is not equality (`separated_from_other_root`,
   `attributed_to_this_*_root` — overlap never *identifies* a root).
3. A tolerance may trigger refinement or `Unresolved`; it may not create
   topology (the whole `LocationOnPiece` discipline).
4. Only certified `Exterior` may be silently discarded (intersection.rs:86).
5. Shared source identities outrank coordinate comparison (`pair_identity`,
   `shared_source_vertex`, the `SourceVertexKey` admission routes).
6. No principal-branch `atan2` result decides source traversal topology (A8).
7. Rounded coordinate differences never feed certified predicates —
   `point_diff_exp`/`Expansion::from_sum` is the exact direction everywhere
   (intersection.rs:449, exact.rs:140).
8. A rounded evaluated arc endpoint is not automatically exact semantic
   geometry (the entire endpoint-admission machinery, A7).
9. Positive-length overlap is not a large collection of point intersections (A3).
10. Unrelated tangency is not silently converted into a crossing or source join
    (`PairUnsupported::UnrelatedTangency`, the `*_source_join` gates).
11. Deck placement is never a nearest-integer round (`DeckSolveResult`,
    deck.rs:59).
12. Candidate translation enumeration has no false negatives (`deck_cover_interval`,
    deck.rs:754) — D16 / Lemma 1.

## 5. Certification vs. representative-data boundary

The rule, already operative in ARR-002, that GEN-001 generalizes:

- **Certified** (may decide topology): exact expansion signs; directed-rounding
  interval separation; certified parameter enclosures; shared source identity;
  certified attribution of an isolated root to an authoritative endpoint
  parameter; certified branch/germ behavior (new); deck displacement from
  `DeckSolveResult::Unique`; translated-copy candidacy from `deck_cover_interval`.
- **Representative** (rendering / evaluation / ordering-seed only, never
  identity): `CertifiedIntersection2.point`; `arc.start_point()`/`end_point()`
  evaluated coordinates; `parameter_hint_interval` midpoints; the rounded `dc`
  in circle–circle; `interval_atan2` angle enclosures (ordering key only).
- **Typed non-results** (never silently coerced): `LocationOnPiece::Undecidable`,
  `PairUnresolved`, `MonotoneDecompositionFailure::InteriorClassificationUndecided`,
  `DeckSolveResult::Indeterminate`, `CertifiedDeckInterval::Indeterminate`,
  and — to be added — germ-level `Unresolved`/`Unsupported`.

GEN-001 adds one new clause: **the branch germ is certified, the representative
point is not, and ARR-003 consumes germs — not representatives — for ordering
and topology.**

## 6. Generic contracts (sketch; names provisional, semantics normative)

These are the ARR-003-facing types GEN-001 freezes. Field lists are minimal, not
exhaustive.

```text
CurveSpan2
  span_id, source occurrence/provenance, authoritative param domain,
  traversal direction, certified evaluation enclosure, derivative/branch info,
  optional analytic fast-path tag, deterministic debug repr.
  Variants (or sealed-trait impls): AnalyticLine, AnalyticCircularArc,
  RationalBezier.  Analytic circles are NOT forced through Bézier.

BranchGerm
  Regular{first_nonzero_order:1}
  StationaryRegular{first_nonzero_order:k}
  CuspCandidate
  Singular
  Unresolved

BranchIncidence        // one curve's involvement in one event
  span id, source occurrence, parameter enclosure OR authoritative endpoint id,
  incoming/outgoing role, certified germ, deck label, provenance,
  representative evaluation hint (NOT identity).

ContactComponent2
  IsolatedEvent(IsolatedEvent2)   // carries an arbitrary number of BranchIncidence
  CommonArc(CommonArc2)           // support fragment, participating occurrences,
                                  // param correspondence, orientation, multiplicity,
                                  // certified basis, endpoint event ids.

EventIdentity          // construction/provenance-based, NEVER coordinate proximity
  SharedSourceVertex | SharedMonotoneCritical | IsolatedRootBox{…}
  | MergedHighMultiplicity{…} | CommonArcEndpoint{…} | DeckTranslated{…}
  | CollapsedStratum(σ).
  A Point2<f64> may be stored for rendering; it MUST NOT define Eq/Ord identity.

DeckRank = Rank0 | Rank1 | Rank2
DeckContext + AmbientLatticeId   // lattice-bound rank context (one per event)
CertifiedDeckLabel + DeckLabelBasis  // validated, lattice-bound label (GEN-001D)
DeckSignature                   // canonical relative (gauge-normalized) label set
DeckLattice          // from period matrix P (rank ≤2)              // deferred
enumerate_translated_copies(B_i, B_j, P) -> finite DeckLabel set   // deferred;
                                // generalizes deck_cover_interval (GEN-001D keeps
                                // rank-2 placement a typed Unsupported)
```

**Deck label discipline (GEN-001D).** A deck vector is meaningful only relative
to a *particular* certified ambient lattice, so `CertifiedDeckLabel` binds every
label to an `AmbientLatticeId` (from the certified generators) and to a
`DeckLabelBasis` naming how it was certified; there are no unrestricted
rank-1/rank-2 public constructors. Absolute lifts are gauge-dependent — adding
one deck vector to every incidence is the same quotient event — so event deck
identity is the canonical **relative** signature (`DeckSignature`), never raw
absolute labels, and periodicity is never inferred by wrapping coordinates
modulo a period. `IsolatedEvent2` carries one shared `DeckContext`; each
`BranchIncidence` carries a validated label and a `CanonicalBranchSide` (the
incidence's canonical participant slot, assigned from the certified sorted
participant pair — not from parameter-enclosure bits, which are evidence only).

`LocationOnPiece` (Interior / IdentifiedEndpoint / Exterior / Undecidable) is
already family-agnostic and is reused as-is.

## 7. Implemented vs. deferred algorithms

**Already implemented, reuse as-is:** Shewchuk `Expansion` + `CertifiedInterval`
(exact.rs); exact coordinate-difference discriminants (intersection.rs); the
rank-1 deck solver and D16 cover interval (deck.rs); the rank-parametric ambient
authority (ambient.rs); the five-factor orientation tripwire
(source_evidence.rs); the certified circle-vs-ellipse adapter (circular_arc.rs).

**To implement in GEN-001:** the §6 contracts; the ARR-002 adapters (line/line,
line/circle, circle/circle → `ContactComponent2`, preserving every diagnostic);
one polynomial Bézier `CurveSpan2` reaching the generic root/contact substrate;
generic x-critical / derivative-zero isolation via Bernstein hull + subdivision
(+ interval Newton where valid), with `Unresolved` for inseparable clusters;
certified W-nonvanishing on a Bézier span (Bernstein coefficient signs);
derivative-jet germ classification; the germ-based replacement for the chord-side
test (A7). GEN-001D delivered the certified rank/deck layer (lattice-bound
labels, canonical relative signatures, the rank-1 adapter) but **not** rank-2
translated-copy enumeration: that generalization of `deck_cover_interval` to a
period matrix stays deferred, so rank-2 geometric placement is a typed
`Unsupported`, not a guess.

**Deferred (interface must not preclude):** full NURBS/B-spline import (clean
rational-span support suffices for GEN-001); full bivariate certified root
isolation cascade (one working Bézier + `Unresolved` for the rest suffices);
full common-factor / subresultant / implicitization overlap extraction; generic
implicit curves; quotient DCEL, homology, cut-open planning; production
activation. Each is named behind the frozen interface so it can be added
monotonically (FORMAL_SYSTEM §XIX).

## 8. Compatibility with ARR-003 … ARR-006

- **ARR-003 (sweep):** consumes `BranchIncidence` + `ContactComponent2` under
  `EventIdentity` with no family `match`. High-multiplicity events are one
  `IsolatedEvent2`; overlaps are one `CommonArc2`. Event ordering uses certified
  enclosures + identity, never representative coordinates. Deck labels ride on
  every record. The pairwise solver feeds branch records; ARR-003 merges.
- **ARR-004 (DCEL / material solve):** vertex canonicalization via `EventIdentity`
  (no geometric welding); half-edges carry deck displacement and physical/
  artificial kind; rotation system uses germs to distinguish crossing from
  tangent; the §X constraint solve and §XI link conditions consume the typed
  outcomes. Native/Singular endpoints (A5) become reachable only when the seam
  certifies strata.
- **ARR-005 (realization):** polygonalization approximates the generic span
  within declared error; the germ/identity model guarantees tessellation
  tolerance never decides connectivity (A4). Shared-boundary vertices reuse
  identical event identities.
- **ARR-006 (corpus / activation):** classifies every face outcome over the
  typed result lattice; the chord-side fix (A7) and germ model are what make
  metamorphic invariance (permutation, reversal, translation) provable rather
  than lucky.

## 9. Supported and unsupported input envelopes (after GEN-001)

- **Supported (admitted toward topology):** analytic line and circle spans
  (unchanged); one polynomial Bézier span through the generic substrate; rank-0,
  rank-1, and rank-2 deck *labels* (lattice-bound, validated, gauge-normalizable);
  rank-1 geometric placement through the existing axis-aligned solver; isolated
  transverse and endpoint intersections; certified same-orientation and
  opposite-orientation common arcs from identical support; regular and
  stationary-regular germs.
- **Unsupported (typed `Unsupported`, not crashes):** unresolved curve overlaps
  beyond the minimal cases; coincident support circles; unrelated tangency;
  non-circular affine images (circle-vs-ellipse negative); general rank-2

### GEN-001C notes (what shipped, what is deferred)

The bounded scope (§12, option R) was taken. `bezier_isect.rs` delivers:

- the denominator-cleared system `F = X1·W2 − X2·W1`, `G = Y1·W2 − Y2·W1` as
  tensor-Bernstein interval polynomials (solver-private), with the exact
  binomial-weight Bernstein product;
- a deterministic depth-limited branch-and-bound over `[0,1]²` whose exclusion
  is Bernstein range sign-definiteness (sound only because both weights are
  certified positive) and whose **only** root promotion is a verified interval
  Krawczyk inclusion `K(X) ⊂ int(X)` over directed rounding; box width,
  residual, Newton convergence, subdivision depth, and approximate nonsingular
  Jacobians are never sufficient;
- a pair-level `Complete`/`Unresolved` result: `Complete` only when the whole
  domain is covered by exclusion-certified regions and mutually distinct
  unique-root clusters, and the certified subset of an `Unresolved` result is
  diagnostic only (an unresolved region may hold another root);
- regular branch germs from the tangent numerator `(X'W − XW', Y'W − YW')`
  (zero-containing enclosures refine, then report `UnresolvedStationaryBranch`,
  never an ordinary tangent) and a certified transverse orientation from
  `det(T1, T2)` (indeterminate → `UnresolvedTangencyOrSingularity`);
- the canonical event identity: the sorted span pair plus a deterministic
  pair-local root ordinal (`EventIdentity::IsolatedRoot`), replacing the
  provisional per-curve `index`. Operands are canonicalized to source
  orientation and sorted order before solving, so swap, reversal, and
  deterministic repetition give the same identity. The ordinal is an immutable
  root id of the unsplit pair's isolation; `refer_back_to_parent` re-binds roots
  found in derived (subdivided) sub-pairs back to the parent's root ids, the
  registry contract ARR-003 will drive.

**Deferred (typed `Unresolved`, never guessed):** clustered and multiple roots,
singular Jacobians, stationary and tangential contacts, Bézier roots lying
exactly on a parameter-domain boundary (`UnresolvedBoundaryRoot`; no endpoint
certificate yet), and common algebraic components. The A7 chord-side repair for
the analytic fast path (germ-based orient test with the same conservative
outcomes) is bounded to GEN-001C's germ machinery and is not yet applied to the
analytic `intersect_x_monotone` path.

### GEN-001D notes (what shipped, what is deferred)

The rank/deck milestone generalizes the generic span, branch, contact and event
contracts to carry Rank 0/1/2 deck labels cleanly, **reusing** the repository's
existing ambient and deck machinery rather than building a parallel arithmetic.

**Authoritative reused types.** `ambient.rs::CertifiedAmbientLattice`
(+ `CertifiedRank0/1/2`, `resolve_ambient_periods`) remains the authority for
certified ambient rank/lattice; `ambient.rs::DeckVector0/1/2` and
`DeckDisplacement` remain the rank-parametric deck vectors with checked algebra;
`deck.rs::solve_axis_aligned`/`DeckSolveResult` remains the certified rank-1
axis-aligned placement solver. Nothing parallel was introduced. The older
`domain/deck.rs` (`LatticePotential` union-find) is a different seam-potential
mechanism used by `domain/projection.rs`; it is retained and is not authoritative
for certified labels.

**Rank representation.** Rank 0 = `{0}`, Rank 1 = `Z`, Rank 2 = `Z²`. A deck
vector is meaningful only relative to a *particular* certified ambient lattice:
`AmbientLatticeId` (derived from the certified generators in
`CertifiedAmbientLattice::deck_context`) is the binding token, and `DeckContext`
carries one per event. `CertifiedDeckLabel` is rank-tagged, lattice-bound and
basis-tagged (`DeckLabelBasis`), with private fields and no unrestricted
rank-1/rank-2 public constructors: the public routes are the certified zero
(`zero`, certified by rank) and in-crate certified placement/transport. A label
from a different lattice — even of the same rank — is a typed
`DeckLabelError::LatticeMismatch`, never a silent truncation, padding or
reinterpretation.

**Gauge normalization (canonical relative signature).** Absolute lifts are
gauge-dependent (`k_i → k_i + h` is the same quotient event), so raw absolute
labels never determine event identity. `IsolatedEvent2::deck_signature` orders
the incidences canonically by `CanonicalIncidenceId` (source occurrence +
`CanonicalBranchSide`, assigned by the producer from the canonical sorted
participant pair — never parameter-enclosure bits, representative points,
insertion or discovery order), selects the canonical minimum as anchor, and
subtracts the anchor label from every label. `DeckSignature::normalize` is the
single canonical construction route; it rejects empty/rank-inconsistent/cross-
lattice inputs. The signature is invariant under input permutation, operand
swap, source traversal reversal, deterministic repetition, subdivision
(inherited lift context) and common deck translation. `IsolatedEvent2::pair_contact_lift_key`
(`PairContactLiftKey`) pairs the signature with the pair/lift construction
identity and is explicitly **not** a final vertex identity: ARR-003 aggregates
an N-way event's equivalence class and produces `AggregatedQuotientEventKey`
(defined here for representability, populated by ARR-003).

**Supported adapters.** `adapt_axis_aligned_placement(context, DeckSolveResult)`
maps the existing four-way solver verbatim: `Unique(k)` → one lattice-bound
label, `NoCompatibleInteger` → `Incompatible`, `MultipleCompatibleIntegers` →
`Ambiguous` (never an arbitrary label), `Indeterminate` → `Unresolved`, and
overflow → `OperationalFailure`. `label_branch_from_placement` attaches a unique
label to an event branch end to end (no near-integer rounding; out-of-range
index is a typed `NoSuchBranch`). Rank-0 analytic and Bézier contact behavior is
unchanged: zero labels in the unique rank-0 context.

**Deferred Rank-2 placement.** Rank-2 *labels* are carried and validated
(checked algebra, lattice binding, canonical normalization, synthetic tests),
but general Rank-2 geometric placement (`d = m·g₁ + n·g₂` from a displacement
enclosure) has no certified solver yet and is a typed
`DeckPlacementResult::Unsupported` via `certify_rank2_placement`. No
lattice-reduction or closest-vector algorithm was invented in this milestone;
the `DeckLattice`/`enumerate_translated_copies` generalization in the §6 sketch
remains deferred.

**Boundary with ARR-003.** GEN-001D adds no sweep event queue, status ordering,
event scheduling, stale-event invalidation, N-way aggregation algorithm, DCEL,
face walks, material-cell equations, triangulation, or production activation.
Synthetic N-way event records appear only in contract tests. The
`AggregatedQuotientEventKey` is representable but empty until ARR-003 certifies
the complete event equivalence class.

## 12. Open decision (requires sign-off before GEN-001B)

The Phase 2–3 scope. Two viable bounds:

- **(R) Bounded — recommended:** deliver the §6 contracts, ARR-002 adapters, the
  chord-side germ fix (A7), rank-2 deck enumeration, minimal overlap, and
  *one* working polynomial Bézier validating the abstraction; return `Unresolved`
  for clustered roots the cascade cannot separate.
- **(F) Full:** additionally ship the complete Bernstein-subdivision + interval-
  Newton + adaptive-precision bivariate isolation cascade now.

(R) keeps the milestone bounded while proving the abstraction has a second curve
family and giving the germ/derivative-jet machinery a real test subject. (F) is
research-grade and can swallow the milestone. The hardest single correctness
gate either way is the same: **certify that the homogeneous weight `W` does not
vanish on the active span** (Bernstein coefficient signs; subdivide when
indeterminate) — if `W` can vanish, hull-based exclusion is unsound.

ARR-003 remains unopened either way.
